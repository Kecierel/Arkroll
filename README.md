## 界面与导航

网站图标采用石墨灰底、白色方框及三个方形骰点，右上骰点为冷青。浏览器图标、品牌标识及PNG图标使用同一设计。

采用石墨灰工作台布局，使用现有干员头像、职业图标、黑白信息层级和小面积冷青操作色。桌面侧栏与手机底部导航均提供抽取、干员库、历史与收藏、设置四个入口。预先随机的内容选择与每职业人数集中在配置区，主题在页面内下拉选择。单干员与即时候选采用头像、名称和操作并排的紧凑卡片，手机端操作移到下一行。即时随机提供随机开局与途中随机，按实际招募券手选职业，确认招募后排除本局已招募干员。

切换页面从页顶开始；当前页内操作保持阅读位置。当前版本在桌面品牌下方、手机页头右侧以单行小字显示，应用内版本号统一读取package.json。

字体优先使用设备上的Noto Sans SC，缺失时回退微软雅黑和无衬线字体；无在线字体请求。设计参考及许可见[第三方声明](THIRD_PARTY_NOTICES.md)。

抽取页分别统计总六星干员、已拥有、已启用数量。总数依据当前公共名单快照，拥有和启用独立计算。预先随机与单干员历史按职业分行，即时随机整局历史按确认招募顺序展示开局和途中干员。

## 随机模式

| 模式 | 生成内容 |
| --- | --- |
| 预先随机 → 随机分队和组合 | 当前主题的分队、招募组合，以及八职业各1／2／3名有序6★干员 |
| 预先随机 → 仅随机干员 | 八职业各1／2／3名有序6★干员 |
| 单干员随机 | 从全部启用的6★干员中抽一名 |
| 即时随机 → 随机开局 | 手选主题，按需随机分队和招募组合，从所选职业中抽一名6★干员 |
| 即时随机 → 途中随机 | 从当前所选职业中抽一名6★干员，排除本局已确认招募的干员 |

选择“随机分队和组合”后，在页面内的下拉框选择集成战略主题，支持傀影、水月、萨米、萨卡兹、岁和黑流树海六主题。主题规则核对日期为2026-10-21；黑流树海仍在更新。分队和招募组合的范围在设置页按主题管理，不自动判断游戏解锁进度。规则与来源见 [数据来源](DATA_SOURCES.md)。

预先随机的两个选项共用每职业人数，默认1名。第1／2／3名依次约束该职业前几次六星招募，之后自由选择；不代表开局即可招满。游戏随机职业券、希望与局内效果以游戏实际结果为准。

### 即时随机

选择主题后，可分别打开“随机分队”和“随机招募组合”，各自抽取或重抽，范围与设置页共用。然后根据游戏实际职业券，手动选择1至8个职业，开局通常选择三个；从所选职业的全部已启用六星中等概率抽取一名，每次重抽可能再次抽到相同干员。某个职业没有候选时，其余所选职业仍可抽取；合并后没有候选则提示调整。

抽取后点击“已招募”才加入本局记录并自动排除，同时清空职业选择，下一次重新选择实际职业券。放弃或重抽的候选仍可参与。本局记录可逐条撤回，撤回后该干员按当前启用状态重新参与候选，其他记录及当前待确认结果保留。确认开局干员后进入途中，也可以直接使用途中随机。确认前会重新检查当前资格，被禁用、已招募或不在所选职业内的候选无法确认。改变职业选择会清除该阶段待确认结果。网站只记录在此确认的干员，游戏中的希望、是否招募及其他自行招募由用户判断。

即时随机本局的主题、独立开关、开局配置、职业选择、待确认结果和已招募记录刷新后保留，并纳入JSON备份。产生分队、招募组合、待确认干员或招募记录后显示红色“结束本局”，确认结束会清空结果、职业选择及本局记录，保留主题和开关偏好。更换主题会结束当前局，已有结果或记录时先确认。确认过任何干员后继续使用途中随机，重新随机开局需先结束本局。进行中的记录在即时随机页展示，结束时归入整局历史。

## 使用规则

- 干员库可搜索并分别设置拥有、启用状态。**抽取只依据启用状态**，未拥有但已启用也可参加；新增干员默认未拥有、已启用。
- 预先随机与单干员随机支持生成、逐名重抽、锁定、解锁、复制与收藏。同职业不重复；每名独立锁定，重抽排除同职业其他位置并优先避开自身旧结果，没有替代者时保持不变。一键锁定只锁定已有结果。
- 切换人数保留前列结果与锁定，新增末位留空等待抽取，减少时移除末位并提示；统一调整所有主题会话，不自动抽取或新增历史。
- 某职业候选不足时列出可用、所需及缺少人数，取消本次整套生成，分队、招募组合及干员原结果均保留。锁定结果占用对应位置，即使之后被禁用仍保留；解锁重抽或恢复历史时按当前资格检查。
- 页面导航和模式切换保留当次结果。预先随机与单干员随机的会话独立，打开或刷新会清空这两类模式的结果和锁定，保留每职业人数、模式、主题、范围、干员状态、练度、要求偏好、提示开关及历史收藏。**即时随机本局刷新后继续保留**。
- 默认头像随站部署；职业图标帮助识别结果和干员库。图片加载失败保留占位、文字与操作。
- 操作提示顶部悬浮约2秒，可在设置中关闭。

### MAA 导入

在设置中选择 MAA“小工具 → 干员识别”导出的JSON，核对统计预览后确认。文件在浏览器本地解析，不上传服务器。

确认会覆盖全部干员库的拥有、启用和练度记录。每次导入默认关闭练度筛选：已拥有者启用，未拥有或未列出者设为未拥有、未启用。勾选“排除未达到练度要求的干员”后才显示练度要求选择框，提供“无要求”“精二1级”“精二60级”。选择无要求时，已拥有者均可启用，包括练度未知或未养成者；选择精二要求时，已拥有但未达标或练度未知者保留拥有、取消启用。精一高等级不算达到精二要求。确认导入时，干员库的当前要求同步为本次实际应用值：未勾选排除或选择无要求均显示无要求；选择精二1级/60级则显示相应要求，取消不改变已有要求。

预览显示要求、启用人数，以及未达标和练度未知的数量与名单。缺失或无效练度记为未知，不沿用旧记录；当前结果、锁定及历史收藏保留。预览、取消和格式错误不修改配置。当前没有完整的逐干员导入差异列表或撤销导入；重要配置请先导出备份。

干员库对已拥有干员显示已保存练度，点击名字可编辑练度，并显示当前练度要求；已拥有且已知练度不足的干员标注“未达到当前练度要求”，未知练度单独显示。筛选按钮可展开或收起预览，收起不会保存临时选择；当前要求以最后确认的选择为准。新配置默认无要求，已有精二要求保留。重新筛选只重算启用状态：无要求时已拥有者启用、未拥有者禁用；有精二要求时还须达到要求，会覆盖手动启用选择；确认后仍可手动调整。记住上次确认的要求，再次导入仍默认关闭筛选。练度来自手动编辑或最近一次 MAA 导入，不自动跟随游戏更新。

没有 MAA 也可手动维护练度：先勾选“拥有”，点击干员名字，选择精英阶段和等级并保存。精零、精一、精二分别允许1–50、1–80、1–90的整数等级；可取消编辑或清除为未知。保存练度不会自动改变启用状态，需要时再预览并确认筛选。重新导入 MAA 会覆盖手动练度。

批量操作栏的“使用MAA配置”会以最近一次确认导入的 MAA 配置恢复拥有状态，保留当前练度，并按当前练度要求重新筛选启用：无要求时已拥有者启用（含练度未知者），有精二要求时还须达到要求；未拥有者禁用。预览后确认生效，当前要求、结果、锁定及历史保持不变。例如当前精二30级、要求精二60级的干员，恢复拥有后仍不启用。快照随本机配置和备份保存，下一次确认MAA导入会替换它。旧配置没有快照时，需要重新导入并确认一次MAA文件。

各随机模式的结果卡片显示已拥有干员的当前练度。未拥有者在干员库和随机结果中均不显示练度，也没有编辑入口；手动取消拥有会保留隐藏记录，重新勾选后恢复显示。

### 历史与收藏

预先随机的两种内容与单干员随机的完整全局生成自动保存快照，包含模式、每职业人数、有序干员快照与规则；随机分队和组合还保存主题、分队及招募组合。单项重抽不自动新增历史，可手动收藏当前完整结果。即时随机在结束本局或切换主题时，至少有一名最终确认招募的干员就保存一条整局历史。记录包含原主题、已抽取的分队和招募组合，以及按确认顺序排列的开局与途中名单、职业及确认时间。撤回的干员与待确认候选不进入结束名单。仅抽取开局配置、未确认或全部撤回的局跳过历史保存。

整局记录支持查看、收藏、备注、复制和删除，与其他模式共用历史及收藏上限，随JSON备份保存。结束时归档与本局重置一起写入配置，取消结束或主题切换会保留当前本局。历史使用结束时的快照，后续干员库启用状态变化不影响回看。

未收藏历史最多30条，超出移除最早记录；收藏独立保留最多100条，备注最多500字。恢复职业模式记录会恢复当次人数、模式与主题，并同步调整其他会话长度；恢复单干员记录不改变每职业人数。恢复按当前资格检查，失效干员在原位置留空并提示，后续位置不前移；保留目标会话对应位置锁定，空位解锁。排除的分队、组合同样留空，不修改候选设置。清理历史保留收藏；删除操作需确认。

## 配置、备份与隐私

配置、历史与收藏只保存在当前网址的浏览器localStorage。换网址、浏览器或设备前，在设置中导出JSON，再到目标环境导入；不同网址不会自动共享，清除浏览器数据可能丢失配置。

JSON备份包含设置、模式与主题范围、每职业人数、有序当前结果及逐名锁定、历史与收藏、已保存练度、要求偏好、最近一次MAA快照及即时随机本局。旧备份缺少练度时视为未知；缺少或无效的要求默认无要求，已有精二1级/60级选择保持。导入会覆盖现有配置；旧备份不含历史时会清空现有历史，缺少即时随机字段时初始化为空本局。显式导入可以恢复有效结果与锁定，预先随机与单干员随机的结果在下一次打开或刷新时清空，即时随机本局继续保留。支持configVersion 1旧备份及旧历史迁移：人数默认1名，原结果与锁定进入第1位；新版备份使用configVersion 2。导入前验证结构、人数与同职业重复结果，失败时不覆盖现有数据。支持旧SAMPLE备份迁移；旧 `settings.ownedOnly` 被忽略。

公共数据随网站部署发布，不在运行时自动连接外部数据源；本工具不连接或操作游戏。

## 本地开发

使用Node.js 24，版本约束见 `.node-version` 与 `package.json`。Windows PowerShell可使用 `npm.cmd`：

```powershell
npm.cmd ci
npm.cmd run dev
```

打开终端显示的网址。检查与生产预览：

```powershell
npm.cmd run test
npm.cmd run build
npm.cmd run preview -- --host 127.0.0.1
```

构建输出为 `dist`；根目录 `index.html` 是源码入口，不能直接双击作为成品。不提供PWA安装、单文件HTML或离线启动。

## 数据与素材维护

公共名单在 `src/data/operators.json`，按稳定ID保留个人状态。修改时同步 `updatedAt` 和来源记录；可用 `scripts/generate-operators.py` 交叉核对本地来源，只输出id/name/profession/rarity。个人MAA及备份文件不得提交；`.gitignore`无法识别所有私人文件名，提交前仍需检查。

应用版本与存储协议分开维护：`configVersion: 2` 用于有序多位置结构，兼容读取旧协议1；存储键继续使用 `arknights-is-randomizer:v1`。协议版本不跟随产品版本自动变化，协议变化必须设计迁移。

头像保留原始PNG及来源清单，展示用141张WebP共约1.84MiB，比原PNG减少77.3%，保持180×180和透明通道。入口低优先级预加载全部WebP，当前结果高优先级加载；实际等待与缓存复用取决于网络和浏览器。

素材维护使用 `node scripts/download-avatars.mjs` 校验、补齐快照（该命令联网），再以支持WebP的Pillow运行 `python scripts/optimize-avatars.py`，生成压缩图、清单与 `src/data/avatarImages.json`。带内容哈希的图片与映射一起提交；常规npm构建无需Python，也不会自动联网下载素材。

职业图标由用户提供，原始下载页面与具体授权条件待补充。素材详情见 [数据来源](DATA_SOURCES.md) 和 [第三方声明](THIRD_PARTY_NOTICES.md)。依赖、构建产物、密钥和个人导出文件不提交。
