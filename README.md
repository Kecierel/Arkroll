🌐 **在线使用：[Arkroll](https://arkroll.pages.dev/)**

**当前最新干员：克莱门莎** <img src="public/avatars/char_4231_clemnt.png" alt="克莱门莎默认头像" width="48" height="48" />

为《明日方舟》集成战略挑战随机选择分队、招募组合和6★干员。纯前端实现，无需账号或后端。

当前源码版本 **0.4.4**。干员数据快照与核对日期见 [数据来源](DATA_SOURCES.md)。

## 三种随机模式

| 模式 | 生成内容 |
| --- | --- |
| 完全随机 | 当前主题的分队、招募组合，以及八职业各一名6★首选干员 |
| 全职业随机 | 八职业各一名6★干员 |
| 单干员随机 | 从全部启用的6★干员中抽一名 |

完全随机支持傀影、水月、萨米、萨卡兹、岁和黑流树海六主题。主题规则核对日期为2026-10-21；黑流树海仍在更新。分队和招募组合的范围在设置页按主题管理，不自动判断游戏解锁进度。规则与来源见 [数据来源](DATA_SOURCES.md)。

完全随机中的干员是整局挑战目标，不代表初始希望足够招募；游戏随机职业券与局内效果以游戏实际结果为准。

## 使用规则

- 干员库可搜索并分别设置拥有、启用状态。**抽取只依据启用状态**，未拥有但已启用也可参加；新增干员默认未拥有、已启用。
- 支持生成、单项重抽、锁定、解锁、复制与收藏。锁定保护已有结果，锁定后对应重抽禁用；必要候选为空时生成保留整套结果并提示。
- 页面导航和模式切换保留当次结果，各模式与主题会话独立。**打开或刷新页面会清空全部结果和锁定**，保留模式、主题、范围、干员状态、练度、要求偏好、提示开关及历史收藏。
- 默认头像随站部署；职业图标帮助识别结果和干员库。图片加载失败保留占位、文字与操作。
- 操作提示顶部悬浮约2秒，可在设置中关闭。

### MAA 导入

在设置中选择 MAA“小工具 → 干员识别”导出的JSON，核对统计预览后确认。文件在浏览器本地解析，不上传服务器。

确认会覆盖全部干员库的拥有、启用和练度记录。每次导入默认关闭练度筛选：已拥有者启用，未拥有或未列出者设为未拥有、未启用。练度要求提供“无要求”“精二1级”“精二60级”。选择无要求时，已拥有者均可启用，包括练度未知或未养成者；选择精二要求时，已拥有但未达标或练度未知者保留拥有、取消启用。精一高等级不算达到精二要求。

预览显示要求、启用人数，以及未达标和练度未知的数量与名单。缺失或无效练度记为未知，不沿用旧记录；当前结果、锁定及历史收藏保留。预览、取消和格式错误不修改配置。当前没有完整的逐干员导入差异列表或撤销导入；重要配置请先导出备份。

干员库对已拥有干员显示已保存练度，点击名字可编辑练度，并显示当前练度要求；已拥有且已知练度不足的干员标注“未达到当前练度要求”，未知练度单独显示。筛选按钮可展开或收起预览，收起不会保存临时选择；当前要求以最后确认的选择为准。新配置默认无要求，已有精二要求保留。重新筛选只重算启用状态：无要求时已拥有者启用、未拥有者禁用；有精二要求时还须达到要求，会覆盖手动启用选择；确认后仍可手动调整。记住上次确认的要求，再次导入仍默认关闭筛选。练度来自手动编辑或最近一次 MAA 导入，不自动跟随游戏更新。

没有 MAA 也可手动维护练度：先勾选“拥有”，点击干员名字，选择精英阶段和等级并保存。精零、精一、精二分别允许1–50、1–80、1–90的整数等级；可取消编辑或清除为未知。保存练度不会自动改变启用状态，需要时再预览并确认筛选。重新导入 MAA 会覆盖手动练度。

批量操作栏的“使用MAA配置”会以最近一次确认导入的 MAA 配置恢复拥有状态，保留当前练度，并按当前练度要求重新筛选启用：无要求时已拥有者启用（含练度未知者），有精二要求时还须达到要求；未拥有者禁用。预览后确认生效，当前要求、结果、锁定及历史保持不变。例如当前精二30级、要求精二60级的干员，恢复拥有后仍不启用。快照随本机配置和备份保存，下一次确认MAA导入会替换它。旧配置没有快照时，需要重新导入并确认一次MAA文件。

三种随机模式的结果卡片显示已拥有干员的当前练度。未拥有者在干员库和随机结果中均不显示练度，也没有编辑入口；手动取消拥有会保留隐藏记录，重新勾选后恢复显示。

### 历史与收藏

三种模式的完整全局生成自动保存快照，包含模式、干员与规则；完全随机还保存主题、分队及招募组合。单项重抽不自动新增历史，可手动收藏当前完整结果。

未收藏历史最多30条，超出移除最早记录；收藏独立保留最多100条，备注最多500字。恢复会切换到记录对应的模式与主题，并检查当前资格：禁用干员或排除的分队、组合留空并提示，不修改候选设置。清理历史保留收藏；删除操作需确认。

## 配置、备份与隐私

配置、历史与收藏只保存在当前网址的浏览器localStorage。换网址、浏览器或设备前，在设置中导出JSON，再到目标环境导入；不同网址不会自动共享，清除浏览器数据可能丢失配置。

JSON备份包含设置、模式与主题范围、当前结果及锁定、历史与收藏、已保存练度、要求偏好及最近一次MAA快照。旧备份缺少练度时视为未知；缺少或无效的要求默认无要求，已有精二1级/60级选择保持。导入会覆盖现有配置；旧备份不含历史时会清空现有记录。显式导入可以恢复有效结果与锁定，下一次打开或刷新仍清空它们。支持旧SAMPLE备份迁移；旧 `settings.ownedOnly` 被忽略。

公共数据随网站部署发布，不在运行时自动连接外部数据源；本工具不连接或操作游戏。

## 本地开发

使用Node.js 24，版本约束见 `.node-version` 与 `package.json`。Windows PowerShell可使用 `npm.cmd`：

```powershell
npm.cmd ci
npm.cmd run dev
```

打开终端显示的网址。检查与生产预览：

```powershell
npm.cmd run test
npm.cmd run build
npm.cmd run preview -- --host 127.0.0.1
```

构建输出为 `dist`；根目录 `index.html` 是源码入口，不能直接双击作为成品。不提供PWA安装、单文件HTML或离线启动。

## 数据与素材维护

公共名单在 `src/data/operators.json`，按稳定ID保留个人状态。修改时同步 `updatedAt` 和来源记录；可用 `scripts/generate-operators.py` 交叉核对本地来源，只输出id/name/profession/rarity。个人MAA及备份文件不得提交；`.gitignore`无法识别所有私人文件名，提交前仍需检查。

应用版本与存储协议分开维护：`configVersion: 1`、存储键 `arknights-is-randomizer:v1` 不随应用版本号替换，协议变化必须设计迁移。

头像保留原始PNG及来源清单，展示用138张WebP共约1.80MiB，比原PNG减少77.2%，保持180×180和透明通道。入口低优先级预加载全部WebP，当前结果高优先级加载；实际等待与缓存复用取决于网络和浏览器。

素材维护使用 `node scripts/download-avatars.mjs` 校验、补齐快照（该命令联网），再以支持WebP的Pillow运行 `python scripts/optimize-avatars.py`，生成压缩图、清单与 `src/data/avatarImages.json`。带内容哈希的图片与映射一起提交；常规npm构建无需Python，也不会自动联网下载素材。

职业图标由用户提供，原始下载页面与具体授权条件待补充。素材详情见 [数据来源](DATA_SOURCES.md) 和 [第三方声明](THIRD_PARTY_NOTICES.md)。依赖、构建产物、密钥和个人导出文件不提交。
